# ミリしらソード — ゲーム設計メモ

最終更新: 2026-07-31

この文書は、今後の相談やAIコーディングで決定事項を失わないための基準です。
仕様を変更したときは、実装と同時にこの文書も更新します。

## 現在決まっていること

- PCとスマートフォンの両方でプレイする。
- ゲーム画面は正方形。
- PCでは正方形のゲーム画面を大きく表示する。
- スマートフォンでは上部にゲーム画面、その下に十字キーと日本語／英語の
  2つの斬撃ボタンを置く。
- スマートフォンの十字キーとアクションボタンは、初期UI比で約1.3倍の押しやすいサイズにする。
- PCの方向操作はWASDまたは矢印キー。
- PCの日本語斬りはJ、英語斬りはK、リセットはR。
- スマートフォンのアクションボタンは「あ」の日本語斬りと「A」の英語斬り。
- スマートフォンのリセットはゲーム画面上部のリセットボタンに対応する。
- 見下ろし型で、マス目に沿って移動する。
- 通常プレイはターン制の文字ブロックパズル。文字を1個ずつ押す。
- ゲーム状態は入力されたターンでのみ更新し、描画補間や演出の時間経過で
  敵・視線・勝敗を変化させない。
- 方向入力で移動できない場合はその方向を向くだけで、ターンを消費しない。
- 斬撃は成功、配置失敗、空振りのすべてで1ターンを消費する。
- 通常起動は13ステージから任意の1面を選んでプレイできる。
- 初期選択は会議用の15×15ステージとする。
- 既存の100×100仮ワールドはステージエディター用として維持する。
- 各ステージは専用の固定 `cameraAreas` を持ち、正方形画面へ盤面全体を表示する。
- ブラウザ上のステージエディターで、マス配置と部屋別カメラを編集できるようにする。
- 港街のBGMを音量30%でループ再生する。
- ブラウザの自動再生制限で開始できない場合は、最初のキー入力または画面タップでBGMを開始する。
- UIはシンプルに保つ。仮の段階でゲーム固有の見た目を勝手に決めすぎない。
- ゲーム画面全体で、長押しによる文字選択とスマートフォンのタッチメニューを無効にする。

## コアギミック試作

通常ゲーム起動では、言語による名前の長さと文字の物理利用を検証する
13ステージから、画面上部の選択欄で任意の1面を開始できる。
選択を変更した時点で、ターン、文字、敵、扉、勝敗を選択面の初期状態へ戻す。
疑似オープンワールドとIRIS戦は今回の実装対象に含めない。

### 名前と斬撃

- 斬撃はモード切替ではなく、日本語斬りと英語斬りを常に別入力として用意する。
- 名前付き実体は日本語名、英語名、斬撃可否、未知名かどうかをデータで持つ。
- 正面1マスの実体を斬ると、選んだ言語の正式名称をUnicode grapheme単位で分割する。
- 1文字目を実体の元マスへ置き、残りを斬った方向へ1マスずつ一直線に置く。
- 1マスでも盤外、壁、閉じた扉、別エンティティ、既存文字へ衝突する場合は、
  全文字の生成を取り消して実体も残す。
- 成功、配置失敗、空振りはいずれも1ターンを消費する。

### 文字ブロック

- 1文字につき1マスを使い、プレイヤーは通常1個だけ押せる。
- 2個以上が連続した列は通常押せず、引くこともできない。
- 文字はスイッチに乗り、通路と固定視線を遮り、追跡敵の移動も止める。
- 文字の意味にかかわらず、基本の物理挙動はすべて同じ。
- 未充填の溝へ文字を押すと、その文字は消えて溝が歩行可能な床へ変わる。

### 騎士と視線

- 固定視線敵は一方向を監視し、壁、閉じた扉、文字までを危険マスとして赤く表示する。
- 名前付き実体や生きた敵は視線を遮らない。文字生成は同じターンの視線判定に間に合う。
- 追跡する騎士は消費ターンごとに、列が違えば横へ1マス近づく。
  横の移動先が塞がれている場合は停止し、同じ列にいる場合だけ縦へ1マス近づく。
- 旧試作面の追跡敵は既存解法との互換性のため、横が塞がれた場合に縦へ進む。
  この差はステージデータで指定する。
- 無料の向き変更では追跡敵を動かさず、次の予定マスは常に矢印で表示する。

### 会議用ステージ「六文字の城壁」

- 盤面は15×15で、主人公、騎士、東向き視線敵3体、スイッチ1個、
  扉兼出口1個を配置する。
- 騎士の名前は日本語 `騎士`、英語 `KNIGHT` とし、斬る前からHUDへ表示する。
- 正解誘導後は主人公が0始まり座標 `(7, 7)`、騎士が `(7, 8)` となる。
- 南向き英語斬りで `K` から `T` を `(7, 8)` 〜 `(7, 13)` へ同時生成する。
- `N`、`I`、`G` が3本の視線を遮り、`T` がスイッチを押した同じターンに扉を開く。
- 日本語斬りは `騎`、`士` の2文字だけなので、同じ出口経路では視線に発見される。
- 敗北後は自動でリセットせず、理由と再挑戦操作を表示したままにする。
- ステージデータの `solutionActions` を自動テストで再生し、16ターンでのクリアを保証する。

ターン処理順は、プレイヤー行動、斬撃文字の同時生成、スイッチと扉の更新、
生存中の騎士移動、視線再計算、敗北またはクリア判定の順とする。
斬撃成功で騎士が文字へ変わったターンには、騎士移動は発生しない。

## ワールドと描画の方針

採用する方針は次のとおりです。

1. ステージ全体を論理データとして存在させる。
2. 勇者、敵、仕掛けなどの状態も画面外を含めてワールド側で管理する。
3. Canvasへ描画するのは、その時点のカメラ範囲とその周辺だけにする。

「存在している範囲」と「描画している範囲」を分けます。これにより、画面外の
出来事を扱える一方で、画面外の全タイルを毎フレーム描く必要はありません。

ステージが非常に大きくなり、一度に全データを保持することが問題になった場合は、
後からチャンク単位の読み込みを追加します。現在の規模では、まずステージ全体を
保持する単純な構造を優先します。

## マス移動

- 勇者の正式な位置は整数の `{ x, y }` で保持する。
- 入力1回につき移動先を1マスだけ決定する。
- 壁、イベント、敵との判定には正式な整数座標を使う。
- 見た目だけを短時間補間し、マスからマスへ滑らかに見せる。
- 短く押した場合は従来どおり1マスだけ移動する。
- 会議用ステージの見た目の1マス移動は0.18秒で補間する。
- 方向を押し続けた場合は0.29秒後にリピートを開始し、以後は0.22秒ごとに
  1ターンずつ解決する。
- 各マスで追跡敵、スイッチ、扉、視線を必ず再計算し、長押しで判定を飛ばさない。
- 複数の方向を押している場合は、最後に押した方向を優先する。
- 優先中の方向を離したとき、ほかの方向がまだ押されていればその方向へ自動的に戻る。
- 短い方向入力は見た目の補間中でも1入力1ターンとして直ちに処理し、
  補間完了待ちによって途中の入力を破棄しない。
- 同じ描画フレーム内に複数の方向入力が重なった場合だけ、最新の1件を優先する。
- ボタンを離した後のリピート移動は予約せず、進行中の1マスで停止する。
- スマートフォンの十字キーは、押したまま別方向へ指を滑らせて方向転換できる。
- 自動リピート中も判定は必ず1マス単位で行い、壁やイベントを飛び越えない。

## カメラ

各ステージは `cameraAreas` を持ちます。1つのカメラ領域には次を設定します。

```ts
{
  id: "center-north",
  // このマス範囲に勇者がいるとき
  trigger: { x: 9, y: 0, width: 9, height: 8 },
  // この範囲を正方形画面へ映す（viewのみ0.5マス単位を許可）
  view: { x: 8.5, y: 0, width: 10, height: 10 },
  // 画角変更時の移動時間
  transitionMs: 260
}
```

`trigger` と `view` を分離しているため、「この部屋に入ったら部屋全体を固定表示」
「狭い通路へ入ったら少し寄る」などをステージごとに調整できます。

各ステージは1つの固定カメラを持ち、盤面の長辺に1マスを加えた正方形の
`view` へ盤面全体を収めます。15×15の会議用ステージは16×16の画角です。
カメラ追従は使用しません。

エディター用の仮ステージは100×100マスのつながったワールドで、8行×8列の計64室を
壁と1マス幅の入口で接続しています。部屋の外寸は幅10〜16マス、高さ10〜16マスで
一律ではありません。各部屋の `trigger` と `view` は同じ部屋IDへ紐づいており、
入口を越えて次の部屋へ入ると、その部屋専用の画角へ自動的に切り替わります。
この仮マップとパズル設置基準は動作確認用です。

正方形のゲーム画面で縦横比を崩さないため、カメラの `view` は常に正方形にします。
標準の `view` は部屋の外寸の長い辺に1マスを加え、壁の外側を上下左右それぞれ
0.5マス含めます。現時点では部屋に応じて11×11〜17×17マスへ変化します。
論理座標・当たり判定・`trigger` は整数マスのまま、`view` の座標と大きさだけは
0.5マス単位を許可します。ワールド最外周では存在しない領域を映さず、同じ大きさの
画角をワールド内側へ寄せます。

## コードの責務

- `src/assets/tiles/`: マスへ配置する地形画像
- `src/assets/characters/hero/`: 勇者の方向別画像
- `src/assets/audio/`: BGMなどの音声素材
- `src/game/assets/`: 画像の読み込みとゲーム内で使う素材一覧
- `src/game/audio/`: BGMなどの再生制御
- `src/game/data/`: マップ、開始位置、カメラ領域などのステージデータ
- `src/game/trial/stages.ts`: 選択可能な13ステージの文字列マップと解答入力列
- `src/game/trial/rules.ts`: 描画やDOMへ依存しないターン、斬撃、追跡、視線処理
- `src/game/trial/TrialGame.ts`: 会議用ステージの入力接続、短い補間、Canvas描画、HUD
- `src/editor/`: ステージ下書き、編集画面、検証、JSON入出力
- `InputController.ts`: PCとタッチの入力を共通操作へ変換
- `WorldState.ts` / `Game.ts`: 既存エディターのプレイテスト用ワールド
- `CameraController.ts`: 勇者のマスからカメラ領域を選び、画角を補間
- `stageTypes.ts`: ステージ、タイル、座標、カメラ設定の共通型

今後、ゲーム内容が増えたら、敵・イベント・戦闘などを `Game.ts` へ集中させず、
それぞれのシステムへ分割します。

## ステージエディター

- ゲーム画面右上の `EDITOR`、または `?editor=1` で開く。
- 現在配置できるものは、床、壁、草地、勇者の開始位置、各部屋の
  `puzzleAnchor` とする。
- 敵、仕掛け、装飾など未決定のオブジェクト種別は勝手に追加しない。
  素材と仕様が決まった時点で配置パレットへ追加する。
- 部屋選択ツールでは、押したマスを `trigger` に含む部屋を選択する。
- 「切替範囲」は、その範囲に勇者がいるときに使用するカメラを表す。
- 「表示範囲」は、正方形ゲーム画面へ実際に映すマス範囲を表す。
- 切替範囲と表示範囲はCanvas上でドラッグでき、数値入力でも調整できる。
- 表示範囲をドラッグすると、選択した範囲の外側へ標準で0.5マスずつ余白を加える。
  表示範囲の数値入力は0.5マス単位で調整できる。
- 表示範囲は正方形とし、対応する切替範囲全体を含める。
- 下書きはブラウザの `localStorage` へ自動保存し、明示的な保存ボタンも用意する。
- 通常のゲーム起動では下書きを読まず、`?playtest=1` のときだけ下書きを適用する。
  公開中のゲームが編集端末の下書きで変わることを防ぐためである。
- プレイテスト前に、勇者・パズル位置と壁の重なり、カメラ範囲外の床、
  カメラ範囲の重複、表示範囲などを検証する。
- JSONの書き出しと読み込みに対応し、バックアップと別端末への受け渡しに使う。
- ブラウザはリポジトリ内のソースを直接上書きできない。正式ステージへ採用する際は、
  書き出したJSONをリポジトリ側へ取り込んでコミットする。

## BGM

- 港街のBGM素材は `mirishira-port-town-bgm.mp3` とする。
- 通常再生の音量は30%とし、曲の終端まで再生したら先頭からループする。
- ブラウザが自動再生を許可する場合は読込後に開始する。
- 自動再生が拒否された場合は、PCの最初のキー入力またはスマートフォンを含む
  最初の画面タップを再生開始の合図にする。
- 再生制御は `BackgroundMusic.ts` に分離し、ゲーム進行やCanvas描画へ混在させない。

## エディター用の小部屋とパズル単位

- 以下は既存の100×100エディター用ワールドに限った設計とする。
- `StageDefinition` はつながったワールド全体を表す。
- `RoomDefinition` はその中の小部屋1つを表し、原則としてパズル1問の単位にする。
- 各小部屋は `id`、表示名、侵入判定範囲、カメラ画角、切り替え時間、
  壁を含む実寸 `bounds`、`puzzleAnchor` を持つ。
- 現在の100×100仮ステージは、縦横の共有壁座標から部屋・壁・入口を生成する。
  部屋サイズを変える場合は壁座標を編集し、100行の文字マップは手書きしない。
- カメラの正方形 `view` は各部屋の `bounds` の長い辺と外周0.5マスから
  ステージデータ生成時に計算し、11〜17マスの範囲で部屋ごとに変化させる。
- `rooms` と `cameraAreas` は同じ部屋定義を参照し、部屋とカメラの設定ずれを防ぐ。
- すべての通行可能マスは必ず1つの部屋に所属するよう、ステージ読込時に検証する。
- すべての通行可能マスが開始地点から到達可能であることもステージ読込時に検証する。
- 入口マスは移動先の部屋へ所属させ、入口へ踏み込んだ時点でカメラを切り替える。

## タイル素材の配置と前後関係

- ゲーム内の論理サイズは1マスを1単位として扱い、素材画像の元解像度とは分離する。
- 壁素材 `mirishira-wall-low-256x352.png` は、1マスの幅に合わせて表示する。
- 64pxのマスを基準にした場合、表示サイズは幅64px、高さ88px相当。
- 壁の基準点は下辺中央。壁が所属するマスの下辺中央へ固定する。
- 高さ88pxのうち24pxは1マス上へ飛び出して表示する。
- 壁、勇者、敵、設置物は足元のY座標で並べ、奥から手前の順に描画する。
- 背の高い素材が上のマスへ重なることは、見下ろし表現として意図した挙動。
- 当たり判定は素材全体ではなく、壁が所属する1マスを使用する。

## 勇者素材

- 上下左右それぞれの384×384透明PNGを使用する。
- 入力した方向に対応する画像へ切り替え、画像の回転や左右反転では代用しない。
- 表示サイズは幅・高さ1.25マス。
- 基準点は下辺中央で、勇者が所属するマスの下辺中央へ足元を合わせる。
- 正式な位置と当たり判定は従来どおり1マスの整数座標で扱う。
- 壁や将来の設置物と同じく、足元のY座標で前後関係を決める。
- 現在は方向別の静止画をマス間で補間している。歩行・攻撃アニメーションは未実装。
- 攻撃も上下左右それぞれの512×512透明PNGを使用し、画像の回転や反転はしない。
- J／K／画面の斬撃ボタンを押すと、向いている方向の攻撃画像を0.2秒表示して
  通常画像へ戻す。
- 攻撃画像は通常画像とピクセル密度を合わせて約1.67マスで描画する。
- 攻撃画像の足元基準は画像内の `(256, 448)`。剣が足元より下へ出る方向にも対応する。
- 0.18秒の静止画切り替えは仮実装で、正式な連番アニメーションへ置き換える予定。
